# 产品约定

本文件记录这个项目已经确认过的产品规则。  
后续 AI 在改题目、词表、播放行为、跟读判定、错题本前，先读这里。

## 项目定位

- 这是一个给小朋友用的英语学习项目。
- 交互优先简单、稳定、低认知负担。
- 文案、释义、提示都尽量短句化、儿童化。

## 每日词汇更新规则

用户经常会要求：

- “把之前的听写单词放到日常学习中”
- “把这次的新单词替换进去”
- “把相应发音也一起替换”

当前数据约定（2026-11-11 更新）：

- `src/data/dictationWords.json` 是当前每日词的唯一词源；`dictationWords.ts` 只负责类型和导出。
- 旧每日词保存在 `src/data/archivedDictationWords.json`，继续进入日常学习；归档时保留原 ID，后续新课使用未占用 ID，不能让旧错题记录指向新词。
- `src/data/dailyLearningQuestions.ts` 从这两份不同课次的数据自动生成题目，不另写一份手工词表。
- 两组词的普通/慢速音频都要保留；不能因为替换每日课而删除归档词音频。
- 首页“今日 10 分钟”优先抽当前每日词；“每日 10 题”优先巩固未掌握错词，其余名额优先抽归档词，没有错词时沿用旧词巩固。
- 这两个入口都按“最久没练的排前面”轮换（2026-11-13）：“今日 10 分钟”在当前每日词里轮换，词数超过 10 个时两三轮覆盖全部；“每日 10 题”的归档词名额同样轮换。日期种子只用来打破并列。
- `examples` 保存教材英文原句、中文翻译、音频键和来源。重复词合并，但不同例句都保留。

不要只改一个文件，否则容易出现：

- 听写页还是旧词
- 日常学习还是旧词
- 题目、释义、音频文件名不一致

## 当前播放策略

截至 `2026-11-11`，当前产品约定如下：

- 听写单词模块正常播放：走本地生成的 `public/audio/words/us/*.wav`
- 听写及归档单词慢速播放：走独立生成的 `public/audio/words/us-slow/*.wav`
- 例句正常/慢速播放：分别使用 `public/audio/examples/us/*.wav` 和 `public/audio/examples/us-slow/*.wav`
- 当前沿用已验证的 `New-DailyWordAudio.ps1` / Microsoft Zira Desktop 生成流程，正常和慢速分别合成，不做时间拉伸
- 其他未接入本地音频 catalog 的普通播放，才允许继续回退到统一的美式词典接口
- 不允许前端自己把音频拉慢来伪造慢速
- 基础题库的单词、对话整句及分句也接入 `public/audio/question-bank/us/` 与 `us-slow/`；catalog 从真实题库派生。缺少独立慢速资源时明确提示，不回退到词典拉慢或浏览器慢读。
- 播放失败后再次点击必须重新加载同一个文件（2026-11-13），不能因为地址没变就沿用出错的播放器状态。
- 浏览器拒绝播放（自动播放策略）不等于文件损坏：自动播放被拒不显示报错，点击后仍被拒才提示。
- 音频提示与答题反馈分开显示。音频没播出来不能锁住输入框，也不能覆盖对错反馈。
- 对话填空作答前只播放问句（每个问句都有独立的普通/慢速文件），提交后才播放完整对话。

相关代码主要看：

- `src/lib/phonetic.ts`

- `src/pages/DictationPage.tsx`

## 关于男女声不一致

- 词典接口的音频本身不是同一个说话人录制。
- 所以正常播放出现男声/女声混用，通常是上游音频源特性，不一定是本地 bug。
- 听写单词模块已经切回本地统一音频，不能再用词典接口做普通播放。
- 如果其他模块也明确要求“正常播放统一成一个女声”，同样要优先接入本地统一音频。

## 跟读识别约定

- 已接入基于浏览器 Web Speech API 的跟读判定。
- iPad 端优先提示使用 Safari。
- iPad 端需要开启 Siri，否则语音识别能力可能不可用。
- 跟读使用完整目标的匹配分数；识别出目标中的单个字母或短片段不能单独判为通过。

## 学习记录与统计（2026-11-12）

- 普通练习和听写完成后统一调用 `recordCompletedTraining`，同时保存轻量轮次摘要、分词长期证据、到期任务进度和星星；同轮重放不得重复累计。
- 完整普通练习仍只保留最近 30 轮，但已学资格、累计成绩和学习日期从长期摘要读取，不能被展示历史的截断移除。
- 普通练习里每道题都有答案时立即记录这一轮（2026-11-13），不等点“查看结果”；之后再点“查看结果”不重复记录、不重复发星。还有题没答就离开的轮次不记录。
- 听写对同词的辨义和拼写都答对，且都发生在任务到期后，才算完成对应到期任务；只对一部分不能抵消另一部分的错误。
- 每题保留累计作答数、近 7 日分类错误和最多 3 个独立正确轮次；不无限保存每次原始答案。
- 旧数据只回填确实保存的信息。旧听写只有错词摘要时，不能猜完整题数、正确词 ID 或用时；旧 ID 合并也不能丢失原轮次的成绩。
- 首页、学习中心、家长看板和 CSV 导出共用统计口径；空数据显示 0 或暂无数据，连续学习按本地日期去重，词数按词去重。训练用时为已完成轮次的开始至完成间隔，不代表去除停留后的专注时长。
- “已练过”与手动“已标记掌握”分别展示，不从轮数或一次全对推算掌握词数。
- 中译英提交前只显示中文题意及候选项，隐藏正确英文标题、音标和发音/跟读控制；提交后停留复盘。候选顺序按题目稳定生成，刷新不能重排后改变原评分。
- 听力选择作答前隐藏单词和音标，提交后才显示。对话填空的候选词从整份对话题库按题目稳定生成，同一段对话里其他正确句的动词不作干扰项（2026-11-13）。
- 任何模式的已提交答案在返回或刷新后都保持锁定，不能重答（2026-11-13）。
- 普通拼写和听写复用 `buildSpellingFeedback`，统一处理 iPad 弯撇号，保留孩子的原始输入展示。

## 星星奖励约定

- 右上角星星数量必须读取本地真实记录，不允许继续写死展示数字。
- 每满分完成一次训练，增加 1 颗星。
- 同一轮训练只能发放一次星星，刷新结果页或重复保存不能重复增加。
- 点击右上角星星进入 `/stars`，查看每颗星的获得时间、训练来源和满分记录。

## 错题反馈约定

- 练习或听写答错后，要有错误提示音。
- 完成本轮后，要汇总错误单词。
- 错误单词要进入错题本，方便后续集中复习。

提交后的即时反馈（2026-11-13）：

- 所有选择题和拼写题提交后都停在原题：正确选项标绿，选错的选项标红，孩子自己点“下一题”再走。不允许提交后直接跳题。
- 答对有短促的上行提示音，答错沿用原提示音。
- 听写里点“不会”仍按答错记录一次，但先显示答案（释义或正确单词、例句），不直接跳到下一词。
- 拼写答错或点“不会”后，显示对齐后的逐字母对比和正确单词，并请孩子照着打一遍；可以点“跳过”。照着打只是练习，不改变已保存的成绩，也不重复记错。
- 答案显示后的 0.6 秒内忽略对“下一题 / 跳过”的点击，避免连点跳过答案。
- 答案显示后页面自动滚动，让“下一题”露在底部导航上方，但不能把刚显示的答案（标出的选项、听力题的单词、拼写对比）滚出屏幕。两者放不下时答案优先，按钮靠手动滚动。
- 拼写框里按回车等同“提交”；输入法确认候选的那次回车不算。

## 一周再背与复习选题（2026-11-12）

- 首页、复习页和错题本均提供“一周再背”，复用现有练习及例句复盘。每轮最多 10 题；有足够错词和其它旧词时，约 70% 用于未掌握错词，其余用于旧词巩固。候选不足不重复凑题。
- 错词按累计错误、近七日本地日期内的听写/练习错误、到期未完成任务，以及七天以上未复习情况提高优先级；后续独立轮次答对可适度降权。具体常量只在 `src/lib/reviewSelection.ts` 维护，属于产品经验策略，不表示经过学习效果验证。
- 近七天窗口只用于加分。超过窗口的未掌握错词仍保留复习资格；已标记掌握的词不占错词名额，可以作为普通旧词巩固。
- 周复习不从未见过的新题中凑满 10 题；旧课归档、已有答题记录、错题和复习任务提供旧词候选。
- 间隔复习读取真实到期任务及剩余题目，不再用“距上次答错等于第 1/3 天”猜测任务。指定任务只出该任务的待复习题，最多 10 题一轮。
- 本轮题目 ID、顺序、入口与指定任务范围保存在会话中。答错造成权重变化，只影响后续轮次；刷新恢复当前轮次，不重新抽题。强化重排也同步保存。
- 复习题提交后锁定答案并复盘，包含没有教材例句的归档旧词；返回或刷新不能重答覆盖错误成绩。
- 复习任务不再手工勾选完成。完成一轮后，仅将到期后的真实正确答案计入任务子进度；答错和未作答题保留，未来任务不提前完成。
- “已掌握”目前仍沿用已有手动标记；答对降低选题优先级，不直接等同于掌握。
- 旧词名额在同一层内按“最久没复习的排前面”轮换，没有复习记录的最先，日期种子只用来打破并列（2026-11-13）。“每日 10 题”仍先出归档词；一周再背、间隔复习和错题优先把所有学过的旧词放在同一层，当前课学过的词也会轮到。
- 轮换依据是已保存的学习记录。一轮没做完不算复习过，下次仍是同一批词。
- 选中的旧词当天按固定的打乱顺序出题，每天顺序不同，避免孩子靠先后顺序记词；未掌握的错词仍排在最前。“今日 10 分钟”同样每天打乱。

## 常见需求的默认处理方式

### A. 用户让你替换一批新单词

默认流程：

1. 将旧每日词归档，保留 ID；更新 `src/data/dictationWords.json`，给新词分配未占用 ID
2. 确认听写和自动生成的日常学习题同步，归档词仍在题库中
3. 在临时目录生成新词及例句的普通/慢速音频，验证后复制到正式目录，保留归档词音频
4. 校验词表、题目、例句、音频文件集合与已有错题 ID，再跑 lint、test、build

不要只换词表，不换音频。  
不要只换听写，不换日常学习。

### B. 用户让你“生成相应发音并替换”

默认理解为要同时处理：

- `public/audio/words/us/*.wav`
- `public/audio/words/us-slow/*.wav`

有例句时还要同步生成 `public/audio/examples/us/*.wav` 和 `public/audio/examples/us-slow/*.wav`。每日词和归档词均优先使用本地资源。

### 例句学习与背诵

- 例句放在听写的新词学习卡中，支持中英对照、正常/慢速听读，以及遮住英文看中文背诵。
- 辨义或拼写作答前不渲染例句，避免从句子或翻译中看到答案；提交后才展示。
- 日常学习中，所有选择题和拼写题提交后都停留复盘（带例句的题同时展示例句），再点下一题；保存判题和发星不能重复执行。
- 切词时恢复英文显示并停止上一词音频，不另加背诵强制过关或未经验证的自动评分。

### C. 用户说“读音不够正宗 / 不够清楚 / 有回音”

优先检查：

1. 有没有做前端慢放或时间拉伸
2. 慢速音频是不是模型原生生成，而不是二次处理
3. 正常播放是不是误切到了不统一的本地源
4. 当前参考音频是否干净

不要第一时间再加新后处理。  
先排除“前端拉慢”和“脏参考音频”。

## 输出给用户时要说明的重点

完成后，优先告诉用户：

1. 改了哪些文件
2. 现在的播放逻辑是什么
3. 校验是否通过
4. 还有什么剩余风险

不要只说“已经好了”，要把关键决定说清楚。
